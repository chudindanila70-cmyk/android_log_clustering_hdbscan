Анализ Android-логов: группировка ошибок и автоматическая классификация

Этот проект обрабатывает большой Android-лог, выделяет из него критические сообщения (ошибки, фаталы, предупреждения), **группирует их в кластеры** по смыслу с помощью алгоритма **HDBSCAN**, а затем учит **Random Forest** предсказывать тип ошибки по её тексту.

Зачем это нужно?
В логах Android миллионы строк, и искать похожие проблемы вручную сложно. Кластеризация позволяет сгруппировать **одинаковые или похожие сообщения об ошибках** в компактные группы. После этого можно:
- понять, какие ошибки встречаются чаще всего,
- быстро найти необычные (шумовые) сообщения,
- обучить классификатор для автоматической маркировки новых логов.

Что делает код?
1. Разбирает лог-файл (регулярным выражением) – извлекает дату, время, PID, уровень (E=error, W=warning, F=fatal), тег и текст сообщения.
2. Очищает сообщения от шестнадцатеричных адресов (например, `0xABCD`).
3. Оставляет только строки с уровнями `E`, `F`, `W` (233 тыс. записей из 1.48 млн).
4. Преобразует текст сообщений в числа с помощью TF-IDF (учёт отдельных слов и пар слов).
5. Снижает размерность (SVD, 100 компонент) – упрощает данные, сохраняя ~77% информации.
6. Кластеризует (HDBSCAN) – автоматически находит 767 кластеров, шумовые точки помечает как `-1`.
7. Оценивает кластеризацию метриками Silhouette (~0.97) и Davies–Bouldin (~0.37) – качество очень высокое.
8. Обучает Random Forest предсказывать принадлежность строки к кластеру по SVD-признакам (точность ~82%).
9. Анализирует – показывает примеры сообщений и теги для самых больших кластеров, выделяет важные слова.

 Результаты (кратко)
- Найдено 767 смысловых групп ошибок/предупреждений.
- Крупнейший кластер (почти 22 тыс. строк) – сообщения `getTempInfo error: null, 0` (тег `PTM.FileNodeInfo`).
- Random Forest на тесте достигает 82% точности.
- Самые информативные слова для кластеризации – `error`, `null`, `gettempinfo`, `hme_jpeg_dec_delete` и т.д.
